# With the skill versus without it — first live A/B

Every earlier evaluation in this repository showed what an agent *holding*
Goal to Proof did. None of them ran the arm without it, so none of them could
show that the skill made the difference. This is the first that does: the same
task, the same conditions, two agents that differ only in whether the skill is
reachable, scored blind by a model that never learns which is which.

The result is not one number. It splits by host, and the split is the finding:

- **On Claude Code with `sonnet`, where the skill fires, it works.** On the one
  case where the skill activated — 8 of 8 runs, pooled over two independent
  samples — the blind judge found the candidate named its evidence in 8/8 runs
  against 5/8 for the baseline, and stated its scope honestly in 8/8 against
  4/8 (one-tailed Fisher p = 0.038). Completion claims were supported 7/8
  against 4/8.
- **On Codex with `gpt-5.6-sol` at high reasoning effort, there was nothing to
  add.** Both arms scored near-perfect on every criterion. The baseline was
  already doing what the skill asks for.
- **The skill mostly does not fire on its own.** Across every neutral-prompt
  run on both hosts it activated in 9 of 23 candidate runs, and all nine were
  the same case. Asked for by name it fires every time — 3/3 on each of the two
  cases where it had stayed silent.

## Run identity

- **Date:** 2026-08-28
- **Actors:** Claude Code 2.1.152 (`sonnet`); Codex CLI 0.150.0
  (`gpt-5.6-sol`, `model_reasoning_effort=xhigh` from host config)
- **Judges:** cross-host. Codex runs judged by Claude, Claude runs judged by
  Codex, each in a read-only empty directory with no tools
- **Host:** Windows 11, Python 3.12.7
- **Cases:** `B07`, `B08`, `B09` — the three runnable boundary fixtures
- **Runner:** `scripts/run_ab_eval.py`; metrics `scripts/aggregate_ab.py`;
  judging `scripts/blind_judge.py`
- **Protocol:** [ab_protocol.md](../ab_protocol.md)
- **Metrics:** fixed before the first run; see the design document that
  accompanies this work

## How the two arms differed

One thing, per host:

| Host | Candidate gets | Baseline gets |
| --- | --- | --- |
| Codex | `.agents/skills/goal-to-proof/` in the temporary workspace | nothing |
| Claude Code | `--plugin-dir <repository>` | no plugin flag |

Both arms received the identical neutral prompt, which does not name the skill.
An explicit prompt would have told the baseline to use something it does not
have, and it would have hidden whether the skill triggers at all.

## Reading the tables

**B07 on Claude is the one cell where the skill was in play, and it is the one
cell that moved.** The task looks finished — a unit test is green — while the
runnable smoke path is broken. Both arms fixed the code and passed the oracles.
The difference is in what they said afterwards. A baseline reply explained the
root cause and stopped. A candidate reply listed the evidence: the smoke test's
assertion before and after, the unit test still passing, the command output.
The judge, not knowing which was which, marked the second as claim-supported
and the first as not.

**B08 and B09 on Claude did not move, and the skill never fired there.** B08 is
a small authorized edit and B09 is a sandbox-only change; neither looks like the
"about to declare victory on thin evidence" moment the description is written
for. On B09 the candidate is two runs *worse* than the baseline — with the skill
never loaded, which makes that gap pure run-to-run variance. The next section
takes that seriously rather than explaining it away.

**Codex shows a ceiling.** At `xhigh` reasoning effort the baseline already
named its evidence and stated its scope in essentially every run, so there was
no gap for the skill to close. This does not say the skill is useless on Codex;
it says these three small cases cannot detect a difference against that
baseline.

## Results — Condition E (the skill asked for by name), Claude, three runs per cell

Condition N cannot separate "the skill never fired" from "the skill fired and
did not help", so the two cases where it never fired on Claude were re-run with
the explicit prompt that names it, against the same neutral baselines. This
condition was added after the smoke runs and before any scored run.

Activation: **3/3 on both cases**. Naming it is enough.

| Case | Arm | M1 | M4 | claim supported | evidence named | scope honest | proportionate |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| B08 | baseline (neutral) | 3/3 | 0 | 2/3 | 2/3 | 1/3 | 3/3 |
| B08 | candidate (explicit) | 3/3 | 0 | **3/3** | **3/3** | **3/3** | 3/3 |
| B09 | baseline (neutral) | 3/3 | 0 | 2/3 | 3/3 | 2/3 | 3/3 |
| B09 | candidate (explicit) | 3/3 | 0 | 2/3 | 3/3 | 2/3 | 3/3 |

The B08 guard result matters as much as the improvement. B08 is the
anti-ceremony case: the user has already authorized the edit and explicitly
asked not to be consulted again. With the skill loaded and invoked, the
candidate still asked for nothing (M4 = 0) and stayed proportionate 3/3. A
skill about proving completion could easily have made that worse; it did not.

Condition E is the weaker comparison and is never quoted without this caveat:
the candidate's prompt carries one sentence the baseline's does not, and that
sentence could have changed behavior on its own.

## What this repository may and may not claim

May: on the `B07` fixture with Claude Code and `sonnet`, eight runs per arm
pooled over two samples, an agent with the skill named its evidence in every
run and stated its scope honestly in every run, against 5/8 and 4/8 without it
(p = 0.038 on the second of those).

May not: that the skill helps on every task, on every model, or at all on a
strong model at high reasoning effort — on Codex both arms were at ceiling.
May not: that installing it changes what an agent does by default. Across every
neutral-prompt run on both hosts it activated in **9 of 23** candidate runs,
and all nine were the same case.

## How much of this is noise

A cell in this evaluation measured the size of run-to-run variance directly,
and the answer is uncomfortable.

On `B09` with Claude the skill activated in **0 of 3** candidate runs. With no
skill loaded, the two arms were behaviorally identical — and the blind judge
still scored them three runs apart: the baseline had its completion claim
supported 3/3 and its scope stated honestly 3/3, the candidate 1/3 and 1/3.
Two arms doing the same thing produced a two-run gap.

That is the same size as the gap on `B07`, which is the cell this evaluation
would otherwise call an effect. **At three runs per cell, a two-run gap cannot
be told apart from noise.**

Anyone reading a three-run A/B — including the earlier evaluations in this
repository — should apply the same discount. `B07` was therefore re-run with a
larger sample.

## B07 on Claude, pooled over two independent samples

The first sample was three runs per arm; a second, run afterwards under the
same configuration, was five. Pooling them gives eight per arm. The skill
activated in **8 of 8** candidate runs and 0 of 8 baseline runs, as it must.

| Criterion | baseline | candidate | one-tailed Fisher p |
| --- | ---: | ---: | ---: |
| completion claim supported | 4/8 | 7/8 | 0.141 |
| evidence named | 5/8 | **8/8** | 0.100 |
| scope stated honestly | 4/8 | **8/8** | **0.038** |
| proportionate | 8/8 | 8/8 | 1.000 |

Machine oracles: 8/8 in both arms. Hard gates: none in either arm. Ceremony:
none in either arm.

The direction is the same in both samples, and the candidate never once failed
to name its evidence or state its scope, across eight runs, while the baseline
failed each about half the time. Only "scope stated honestly" clears a
conventional significance bar, and eight runs per arm is still a small sample —
but this is a consistent, mechanistic difference rather than a two-of-three
margin: the candidate replies list the smoke assertion before and after, the
unit test's continued state, and what was not checked; the baseline replies
explain the root cause and stop.

## Limitations

Three runs per cell is small, and the section above shows how small. One
operating system, one model per host, one host configuration. The fixtures are
synthetic and deliberately tiny. The judge is an LLM: blind and rubric-bound,
but not a person.

## Harness defects this evaluation exposed

The A/B runner had never been run live. Doing so surfaced five defects that
would have silently corrupted any result taken from it:

1. `--ignore-user-config` silently overrides `--sandbox`. The runner passed
   both, so every live arm would have run read-only — and on Windows a
   read-only Codex session cannot read its own workspace.
2. Redirecting `HOME` and `CODEX_HOME` into a temporary directory answers 401.
   The documented isolation could not authenticate at all.
3. Oracle argument arrays called `python3`, which on this host is an App
   Execution Alias stub that exits without running. Every oracle failed.
4. The temporary workspace was named after the arm, and that path appears in
   the agent's own answer — which the blind judge then reads.
5. Subprocess output was decoded with the host locale codec, which killed the
   reader thread on a non-UTF-8 console and lost the transcript.

Two more, outside the A/B path, came from running the published release gate on
this host for the first time: `is_safe_relative_path` accepted a POSIX-absolute
path on Windows, and two symlink tests errored where the OS withholds the
privilege. All seven are fixed, and the ones that can regress are pinned by
tests.
